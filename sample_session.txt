--- Heap visualiser ---
Key = (-priority, deadline, order).  The smallest key sits at the root.
A(p3) means task A with priority 3. Equal priorities are broken by deadline,
then by the order in which the tasks were added.
PUSH adds the task at the bottom and swaps it upwards while it beats its parent.
POP swaps the root with the last task, cuts it off, then swaps the new root
downwards until the heap order is restored.

PUSH A(p3)   deadline=2026-11-20
  array : [A(p3)]
  tree  :
                                  A(p3)                               

PUSH B(p5)   deadline=2026-11-25
  array : [B(p5), A(p3)]
  tree  :
                                  B(p5)                               
                                  A(p3)                               
  swaps : swap A <-> B

PUSH C(p5)   deadline=2026-11-15
  array : [C(p5), A(p3), B(p5)]
  tree  :
                                  C(p5)                               
                               A(p3)  B(p5)                           
  swaps : swap B <-> C

PUSH D(p1)   deadline=none
  array : [C(p5), A(p3), B(p5), D(p1)]
  tree  :
                                  C(p5)                               
                               A(p3)  B(p5)                           
                                  D(p1)                               

PUSH E(p4)   deadline=2026-11-18
  array : [C(p5), E(p4), B(p5), D(p1), A(p3)]
  tree  :
                                  C(p5)                               
                               E(p4)  B(p5)                           
                               D(p1)  A(p3)                           
  swaps : swap A <-> E

PUSH F(p5)   deadline=2026-11-15
  array : [C(p5), E(p4), F(p5), D(p1), A(p3), B(p5)]
  tree  :
                                  C(p5)                               
                               E(p4)  F(p5)                           
                           D(p1)  A(p3)  B(p5)                        
  swaps : swap B <-> F

POP  -> C(p5)   (highest priority task leaves first)
  array : [F(p5), E(p4), B(p5), D(p1), A(p3)]
  tree  :
                                  F(p5)                               
                               E(p4)  B(p5)                           
                               D(p1)  A(p3)                           
  swaps : swap B <-> C; swap F <-> B

POP  -> F(p5)   (highest priority task leaves first)
  array : [B(p5), E(p4), A(p3), D(p1)]
  tree  :
                                  B(p5)                               
                               E(p4)  A(p3)

  swaps : swap A <-> F; swap B <-> A

--- Benchmark: push n tasks, then execute all of them ---
Compared structures:
  Indexed heap (ours)   push O(log n), pop O(log n)
  Python heapq          same idea, written in C (shows the best case)
  Sorted list           bisect.insort: push O(n), pop O(n) (list shift, fast in C)
  Unsorted list         push O(1), pop O(n) (scan for the maximum)

      n |  Indexed heap |     heapq |  Sorted list |  Unsorted list
-------------------------------------------------------------------
   1000 |       0.005 s |   0.001 s |      0.000 s |        0.019 s
   4000 |       0.028 s |   0.005 s |      0.016 s |        0.307 s
  16000 |       0.177 s |   0.022 s |      0.311 s |        skipped

How to read this: when n grows 4x, the heap time grows a little over 4x
(n log n), while the unsorted list grows about 16x (n squared).
heapq is faster only because it is implemented in C, not because of a
better algorithm.
